# Benchmark results

Generated by `python bench/run_bench.py` on 2026-09-09. Every number below came out of that command; none is typed by hand.

Machine: CPython 3.11.9 on Windows 10, AMD64. Median of 7 runs after one discarded warm-up.

Dataset: `trades` 200,000 rows (Parquet, 9 columns), `instruments` 120 rows (CSV), `traders` 40 rows (CSV), `daily_prices` 60,000 rows (Parquet).

## How to read these numbers

- **sql-engine** and **pandas** read Parquet from disk on every run. Nothing is cached between iterations.
- **SQLite (memory)** runs against a pre-loaded in-memory database. Loading it took 1.55 s and that cost is *excluded* from every figure in its column. This is not a like-for-like comparison and should not be quoted as one.
- **SQLite (file)** runs against a file-backed database, built in 2.31 s, also excluded. The OS page cache warms up across runs, just as it does for the Parquet files.
- **pandas** implementations are hand-written in `bench/run_bench.py` and read only the columns they need, so pandas gets projection pruning for free.
- sql-engine is pure Python over NumPy; SQLite is a mature C engine. Where SQLite wins, it should. The number worth arguing about is the optimiser column, which compares sql-engine against itself.

## Query descriptions

**`filter_project`** — Narrow filter, two columns out of nine

```sql
SELECT trade_id, price FROM trades WHERE price > 3900 LIMIT 1000
```

**`count_filtered`** — Count with an equality filter

```sql
SELECT COUNT(*) AS n FROM trades WHERE trader_id = 7
```

**`group_by_small`** — Aggregate into 2 groups

```sql
SELECT side, COUNT(*) AS n, SUM(quantity) AS q, AVG(price) AS p FROM trades GROUP BY side ORDER BY side
```

**`group_by_wide`** — Aggregate into 40 groups

```sql
SELECT trader_id, COUNT(*) AS n, SUM(quantity) AS q, AVG(price) AS p FROM trades GROUP BY trader_id ORDER BY trader_id
```

**`selective_scan`** — Three conjuncts, highly selective -- the pushdown case

```sql
SELECT trade_id, price FROM trades WHERE trader_id = 7 AND side = 'BUY' AND price > 2000
```

**`join_group`** — 200k x 120 hash join, then aggregate

```sql
SELECT i.asset_class, COUNT(*) AS n, SUM(t.quantity) AS q FROM trades t INNER JOIN instruments i ON t.instrument_id = i.instrument_id GROUP BY i.asset_class ORDER BY i.asset_class
```

**`join_filter`** — Join with filters on both sides

```sql
SELECT t.trade_id, i.symbol, t.price FROM trades t INNER JOIN instruments i ON t.instrument_id = i.instrument_id WHERE i.exchange = 'CME' AND t.price > 3000
```

**`sort_limit`** — Full sort of 200k rows, top 50

```sql
SELECT trade_id, price FROM trades ORDER BY notional DESC, trade_id ASC LIMIT 50
```

**`distinct`** — DISTINCT over two columns

```sql
SELECT DISTINCT trader_id, venue FROM trades ORDER BY trader_id, venue
```
