## What this is, and what it is not

**This is not a Spider execution-accuracy score and must not be compared with one.** Execution accuracy needs the 20 dev SQLite databases (not in this repository) and an engine that can run Spider's gold queries -- which sql-engine mostly cannot, by design.

What is measured here is **grammar and schema coverage**: of the 1,034 gold queries in the Spider dev split, across 20 databases, how many can this dialect express at all. It turns the Limitations section from a list of adjectives into a number.

| Also bind against the Spider schema | 588 | 56.9% |
| Also bind, after rewriting Spider's double-quoted string literals | 774 | 74.9% |

The last row exists because 186 dev queries write string literals in double quotes (`WHERE Airline = "JetBlue Airways"`). In standard SQL double quotes delimit an identifier, so sql-engine correctly reports no such column; SQLite accepts it through a documented compatibility fallback. That is a literal-quoting difference, not a missing feature, so both numbers are shown rather than picking whichever flatters the engine.

## Parsed but did not bind

These parse as sql-engine SQL but fail name resolution against the Spider schema. The double-quoted-literal group is a quoting difference rather than a missing feature (see above). The rest are sql-engine's deliberately stricter aggregation rule: it refuses `SELECT name, COUNT(*) ... GROUP BY id`, where SQLite silently picks an arbitrary row for `name`.

| Reason | Queries |
| --- | ---: |
| double-quoted string literal (SQLite-only) | 186 |
| bare column with an aggregate | 101 |

## Example of each rejection

**bind: bare column with an aggregate**

```sql
select max(capacity), average from stadium
```

**bind: double-quoted string literal**

```sql
SELECT Country FROM AIRLINES WHERE Airline  =  "JetBlue Airways"
```

**set operation (UNION/INTERSECT/EXCEPT)**

```sql
SELECT country FROM singer WHERE age  >  40 INTERSECT SELECT country FROM singer WHERE age  <  30
```

**subquery**

```sql
SELECT song_name FROM singer WHERE age  >  (SELECT avg(age) FROM singer)
```
